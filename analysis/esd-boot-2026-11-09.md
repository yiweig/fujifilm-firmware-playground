# eSD card boot: working stock-firmware path

Date: 2026-11-09. Live-camera result. The X half boots the stock main
firmware from a raw eSD card, with the camera's NAND untouched. This is
the first confirmed SD-boot path; it is card-level and reversible.

## Result

A 32 GB SanDisk SDXC card (CID `03 53 44 53 4b 33 32 47 85 74 05 5f
a2 01 93 3f`) was written with the vendor `sdset` reserved layout and
the stock 2.00 main image in slot 1. With the card inserted, the camera
powers on into the normal Fujifilm UI with a **"Card not initialized"**
banner (the card is raw eSD, so the running firmware cannot mount it as
a FAT volume). Removing the card and power-cycling returns to the
normal NAND boot.

The NAND image was never written in this experiment. The card is the
only modified medium.

## Card layout

The header was produced on the camera by the vendor `sdset` command
(`0x403063fc` -> `0x40077450`) and then completed offline:

| Offset | Value | Meaning |
| --- | --- | --- |
| `0x00` | `eSD RSV\0` | `asciiName` |
| `0x08` | `0xbeef` | signature |
| `0x0c` | `0x8000` | block size (32 KiB) |
| `0x14` | `0xa2` (162) | slot 1 start block |
| `0x18` | `0x26a` (618) | slot 2 start block |
| `0x1c` | `0xe38400` (14,910,464) | slot 1 length in bytes |
| `0x24` | `0x0edc90` (973,456) | card capacity in 32 KiB blocks |
| `0x28` | `2` | `nrHdr` |
| `0x2c` | `0x40` (64) | reserved A, 2 MiB |
| `0x30` | `0x40` (64) | reserved B, 2 MiB |
| `0x34` | `0x20` (32) | reserved C, 1 MiB |
| `0x38` | `0x1c8` (456) | `nrFw1` |
| `0x3c` | `0` | `nrFw2` |
| `0x40` | `0x0032` | type / boot flag |

Slot 1 starts at block `0xa2` = byte offset **`0x510000`**. The stock
`firmware-main.bin` goes there, padded to 456 blocks (14,942,208
bytes). The written prefix is 20,250,624 bytes.

The header's `+0x40` must be the **exact halfword `0x0032`**. The
vendor header writer's checksummed form (`+0x40 = 0x0a32`,
`+0x4a = 0x2c2c`) suppressed the eSD boot in the live test: the camera
fell back to NAND. `+0x4a` was left zero. This is a card-level
observation; the checksum path is not required for this boot stage.

## The entry patch

The earlier stage loads the slot and enters it at **image `+0x0`**. The
stock image's reset vector at `+0x0` is `EA0003AE` (`b +0xec0`), which
is the NAND-boot path; it black-screens when entered from the eSD boot.
Patching the first instruction to:

```text
EA00007E    ; b +0x200
```

redirects the eSD entry to the image's DRAM-init entry at `+0x200`, the
same entry the proven `0x04f7` handoff uses. With this one-instruction
patch, the stock firmware boots from the card.

Observed matrix:

| Card header type | Image entry | Result |
| --- | --- | --- |
| `0x0000` | stock | normal NAND boot, “Card not initialized” |
| `0x0032` | stock `+0x0` (`b +0xec0`) | black screen, no USB |
| `0x0032` | patched `+0x200` | normal UI, “Card not initialized” |
| `0x0a32` (checksummed) | patched `+0x200` | normal NAND boot |
| `0x0032` | patched + USB/model string patch | black screen |

The last row is the positive-execution evidence: the NAND image was
unchanged, but patching strings inside the card image changed the
result. The card image is being executed. Those USB/PTP strings
(`Digital Camera`, `FUJIFILM DIGITAL CAMERA FINEPIX X-HF1`,
`FUJIFILM-X-HF1`) are used early; do not use them as markers.

## Reproduction

```sh
python3 analysis/build_esd_card.py --entry-200 --raw-type \
    --out analysis/output/esd-boot-card-working.bin
sudo dd if=analysis/output/esd-boot-card-working.bin \
    of=/dev/rdisk6 bs=1m
sync
```

The build verifies the stock image SHA-256
`80350bd2bc37b4ce985742ff85a747f7c7ad1ed9be401534ba57ac3262f1d923`,
sets the header, patches `EA00007E` at image offset 0, and writes slot 1
at `0x510000`.

## Recovery and limits

- **NAND fallback:** power off, remove the card, power on. The camera
  boots the internal NAND normally. This was verified repeatedly.
- **Card recovery:** the eSD header overwrites the card's MBR/FAT. To
  restore the loader/test card, reformat the card and put the stock
  `MAIN.BIN` and `EnableTest.txt` back. The card contents are
  disposable.
- **Do not use the camera's firmware-update menu** while booted from
  the card; it could write the NAND. The eSD boot itself does not.
- **Raw card:** the running firmware cannot mount the card, so
  playback/record-to-card functions are unavailable and the UI shows
  “Card not initialized”. The camera's internal NAND remains the
  normal storage.
- **No independent recovery yet:** this boots the stock image from the
  card through the main firmware's own boot path. It is not a mask-ROM
  or USB-boot recovery, and it does not prove a cold recovery if the
  NAND image is damaged.

## Why `sdboot` was not the path

The shell `sdboot` worker reads only one 512-byte sector into the
destination and jumps (`0x40345c80` -> `0x400778fc` with length 0),
and it uses `+0x1c` as a byte offset. It is a loader jump, not a
full-image loader. The working path is the earlier eSD stage, which
loads the slot and enters `+0x0`; the `+0x200` patch fixes its entry.
